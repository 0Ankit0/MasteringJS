Patching Process Explained

Patching is the "apply changes" phase. It updates the real DOM using the differences discovered during diffing.

1) Add nodes
if (!oldVNode && newVNode) {
  const newNode = render(newVNode);
  parent.appendChild(newNode);
  return;
}

If something is new in the next tree, create it once and append it.

2) Remove nodes
if (oldVNode && !newVNode) {
  parent.removeChild(realNode);
  return;
}

If a node no longer exists in the new tree, remove it from the real DOM.

3) Replace nodes when type/tag changes
if (typeof oldVNode !== typeof newVNode || oldVNode.tag !== newVNode.tag) {
  const newNode = render(newVNode);
  parent.replaceChild(newNode, realNode);
  return;
}

Replacement is used only when a node is fundamentally different.

4) Update text content
if (typeof newVNode === "string" && oldVNode !== newVNode) {
  realNode.textContent = newVNode;
  return;
}

This is one of the cheapest updates and very common in real UIs.

5) Sync attributes
for (const [key, value] of Object.entries(newVNode.props || {})) {
  if (!oldVNode.props || oldVNode.props[key] !== value) {
    realNode.setAttribute(key, value);
  }
}
for (const key in oldVNode.props || {}) {
  if (!(key in newVNode.props)) {
    realNode.removeAttribute(key);
  }
}

The node stays in place; only its metadata is updated.

6) Patch children recursively
const maxLength = Math.max(oldChildren.length, newChildren.length);
for (let i = 0; i < maxLength; i++) {
  diffAndPatch(realNode, oldChildren[i], newChildren[i], i);
}

Recursion keeps nested updates accurate without rewriting the whole tree.

Summary

Patching focuses on precision: add, remove, replace, or update only what changed. That is the core performance benefit behind Virtual DOM style rendering.
