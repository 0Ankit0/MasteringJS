Diffing Process Explained

Diffing is the comparison step that figures out exactly what changed between the previous Virtual DOM and the next Virtual DOM.

What diffing tries to optimize

DOM operations are comparatively expensive. Diffing avoids unnecessary work by producing the smallest set of updates required.

1) Check add / remove / replace cases first
if (!oldVNode && newVNode) {
  // add new node
} else if (oldVNode && !newVNode) {
  // remove old node
} else if (typeof oldVNode !== typeof newVNode || oldVNode.tag !== newVNode.tag) {
  // replace node
}

These checks handle structural changes early. If structure changed, there's no need to do deeper comparisons for that branch.

2) Compare text nodes directly
if (typeof newVNode === "string" && oldVNode !== newVNode) {
  // update text
}

Text updates are very common and should be handled quickly with one simple comparison.

3) Compare attributes
for (const [key, value] of Object.entries(newVNode.props || {})) {
  if (!oldVNode.props || oldVNode.props[key] !== value) {
    // set changed/new attribute
  }
}

This step synchronizes element metadata (id, class, ARIA attributes, data attributes, etc.) without rebuilding the element.

4) Diff children recursively
const maxLength = Math.max(oldChildren.length, newChildren.length);
for (let i = 0; i < maxLength; i++) {
  diffAndPatch(realNode, oldChildren[i], newChildren[i], i);
}

Each child subtree is checked the same way. Recursion keeps the logic consistent from top-level nodes to deeply nested content.

Practical beginner takeaway
  • Diffing does analysis, not direct DOM mutation.
  • Patching applies the result of that analysis.
  • Separating these concerns keeps rendering logic clear and maintainable.
