Understanding Virtual DOM Diffing and Patching

This page explains the whole flow in beginner-friendly steps: how we create an "old" Virtual DOM, create a "new" Virtual DOM, compare them, and then update only the changed parts of the real DOM.

Step 1: Build the old Virtual DOM

First, we convert the current page into a plain JavaScript object tree. This gives us a snapshot of the UI before any updates happen. 

const oldVNode = {
  tag: "div",
  props: { id: "app" },
  children: [
    { tag: "h1", props: {}, children: ["Hello, Virtual DOM!"] },
    { tag: "p", props: {}, children: ["This is a simple example."] }
  ]
};

Think of this as a lightweight blueprint of your current UI.

Step 2: Build the new Virtual DOM

When new content arrives (for example, from an API call), we convert that content into another Virtual DOM tree. 

const newVNode = {
  tag: "div",
  props: { id: "app" },
  children: [
    { tag: "h1", props: {}, children: ["Hello, Updated Virtual DOM!"] },
    { tag: "p", props: {}, children: ["This content was updated from the server."] }
  ]
};
Step 3: Diff old vs new

Diffing means comparing two trees node-by-node to find exact changes:

  • Changed: <h1> text.
  • Changed: <p> text.
  • Unchanged: Node type and root container.

The key idea: compute the minimum update plan before touching the DOM.

Step 4: Patch the real DOM

After diffing, the app applies only the required changes. This avoids expensive full re-renders and keeps UI updates fast. 

diffAndPatch(document.getElementById("app").parentNode, oldVNode, newVNode);
Common update scenarios
  • Text changed: Update only text content.
  • Node added: Create and append one new element.
  • Node removed: Remove only that element.
  • Attributes changed: Update only changed attributes.

Modern UI libraries (React, Preact, Vue internals) follow a similar "compare, then patch" strategy, though each has its own optimizations.
